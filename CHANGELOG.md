# Changelog

## [Unreleased]

### Added

- Added pi-tmp (`pi-tmp/`, bundled submodule `zmfkzj/pi-tmp`) as the manifest's first extension: it sets Pi's `TMPDIR` to a private on-disk directory, `/var/tmp/pi-${USER}` (a missing, empty or non-plain `USER` such as `..` falls back to the OS account name, refused when neither is usable; 0700, refuses symlinks and foreign directories; `PI_TMP_DIR` overrides), instead of a RAM-backed `/tmp` whose per-user tmpfs quota made Pi crash with `EDQUOT` on bash output writes. Extensions loaded after it see the directory at module evaluation, so orche scratch and the CLIProxyAPI provider's patched-module cache move too. Not part of `/oh-my-pi` (no dependencies or command). The root harness keeps it inside each test session's scratch (`PI_TMP_DIR`, `TMPDIR` restored); `scripts/pi-tmp.test.mjs` checks the manifest order and, through Pi's loader, that a later extension sees the directory at import and in child processes, and runs the submodule's unit tests.

- Pi 1.4.0 support (`@earendil-works/pi-coding-agent` 1.4.0). The eight TypeScript submodules' Pi development dependencies and locks move 1.3.0 → 1.4.0 (pi-commit's `bun.lock` included); host-provided `*` peers, runtime dependencies and extension code are unchanged. `test:compat`, `test:install`, the root harness and Workbench's host check now require 1.4.0. Pi 1.4.0 activates extension tools a resumed or `/tree` branch never recorded unless they use `defaultActive: false` or a non-direct exposure: new `scripts/restore-installed-later.test.mjs` reopens a session recorded without the umbrella with the real browser, physical-desktop and session-bus entries and checks that browser specialist tools, physical-desktop driver tools and `queue_done` stay on demand across resume, `/reload` and `/tree`. CLIProxyAPI's README now names the actually locked provider 1.4.23. See `docs/pi-1.4.0.md` for the upstream changes, their effect here and the checks.

- Pi 1.3.0 compatibility gates: exact host/AI/TUI and package-local dependency checks, exception-safe isolated runtime harness, real persisted resume/reload/new-session and four CLI tool-selection cases, shared GUI/CodeGraph MCP process accounting, actual CLIProxyAPI SSE/tool tests, local HTTP images tests, and Workbench skill consumption through session-bus wake/queue replay. `npm run test:compat` runs the root/package checks; `npm run test:install` exports current dirty/untracked working files with hashes and validates production installation plus clean reinstallation. See `docs/pi-1.3.0.md` for results and explicit live/Python/environment exclusions.

- Dependency check and install commands: every bundled package has `doctor` and `install-deps` subcommands on its own command (`/orche`, `/browser`, `/gui`, `/commit`, `/bus`, `/workbench`, `/codegraph`, and the new `/images`, `/cliproxyapi`, `/computer-use`), and the umbrella's new `extensions/dependencies/` entry adds `/oh-my-pi doctor [package...]` and `/oh-my-pi install-deps [package...]`, which run them for all packages with a per-package section, an overall summary and remediation for every abnormal item. Packages answer on `pi.events` channel `oh-my-pi-extensions:dependencies` (each keeps its own copy of the contract); absent, throwing or timed-out packages are reported without hiding the others. Existing subcommands are unchanged; `/gui doctor` and `/workbench doctor` keep their content and now present the same items. Tests: `scripts/dependencies.test.mjs`, `scripts/dependencies-pi.test.mjs`, the packages' own suites; `npm test` at the root runs the root checks.

### Changed

- Session-bus × orche: a note from another Pi session that arrives while an orche background job runs (delegating modes) now goes straight to the running worker without a confirmation dialog. pi-session-bus offers genuine received notes on the new `session-bus:route` event before waking the session; pi-orche claims a note once its worker accepted it, frames it as untrusted peer input that grants nothing, and main gets an informational, non-waking copy it must not relay. User/main-originated `orche_task_message`, cancel and new-task approval still ask the user. Unclaimed notes (no job, refused hand-off, wake off, hop or rate limit) are delivered as before; routed notes count toward the wake rate. Tests: `session-bus/test/extension/wiring.test.ts`, `session-bus/test/core/policy.test.ts`, `orche/test/extension/task-peer-notes.test.ts`.

- Pi development dependencies and locks of all eight TypeScript packages now target **1.3.0**; host-provided `*` peers remain unchanged. CLIProxyAPI provider remains 1.4.22 and physical computer-use remains 0.1.22. A separate 1.2.0 smoke remains passing; a full older-version matrix is not claimed.
- Browser initialization no longer drops search-enabled/restored deferred tools on resume or reload. Fresh defaults remain unchanged; recorded exposure transitions and explicit negative tool-selection settings are respected without clearing other extensions' late restoration.
- Orche refreshes mode restrictions for late/restored tools before requests and after turns, drops stale one-turn overrides on session restoration, and retains suppressed tools until registration. Deterministic real-host tests cover forbidden direct and nested calls.
- Test isolation supports long scratch paths without changing production security checks. CLIProxyAPI tests refuse non-loopback requests; root and Workbench checks identify the actual SDK and fail on mismatches. Conditional Kimi Coding API/baseUrl override guidance is documented; no user settings are migrated automatically.

### Fixed

- cliproxyapi: the provider's patched Codex module can no longer be broken by its shared file cache. The official provider (1.4.24) writes `<tmpdir>/pi-cliproxyapi-provider/openai-codex-responses-cpa-<hash>.mjs` in place and imports it whenever it exists, so concurrent starts, an older bundle or a separate provider install rewriting that file, or a process killed mid-write could make it import an empty or partial module, after which every `cliproxyapi` request of that session failed. The bundle now computes the module with the provider's own functions and serves it to the provider's import from memory through Node module hooks, publishes the shared file atomically for other processes, refuses any other import from that cache, and does not load the provider when module hooks are unavailable (`cliproxyapi/src/codex-cache.ts`, `cliproxyapi/test/codex-cache.test.ts`).
